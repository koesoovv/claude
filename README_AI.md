# 적응형 급수 보정 (Adaptive Fill Correction)

스마트 정수기의 급수 정확도를 **학습으로** 높이는 모듈입니다.
기존 음향(주파수) 기반 제어 로직은 그대로 두고, 정지 판단 시점에만 개입합니다.

---

## 1. 문제 정의

499회 급수 실험(`trial_summary.csv`) 분석 결과입니다.

| 지표 | 값 |
|---|---|
| 채움 오차 MAE | 2.71 %p |
| RMSE | 4.45 %p |
| 평균 편향 | **−1.23 %p** (항상 조금씩 덜 채움) |
| \|오차\| > 5%p 비율 | **14.6 %** |
| 최악 오차 | −40 %p |

원인을 좁히기 위해 정지 시점의 **내부 추정값과 실측값**을 비교했습니다.

```
Decision_Fill_Pct − Actual_Fill_Pct  =  평균 +3.07 %p  (표준편차 5.30)
```

제어기는 자기 추정값을 정확히 따르고 있었습니다. 문제는 제어 로직이 아니라
**음향 → 수위 변환 추정기가 체계적으로 "더 찼다"고 착각**하는 데 있었습니다.
따라서 제어 알고리즘을 교체하는 대신 추정 오차 자체를 학습해 보정합니다.

또 하나의 발견은 **시간×유량 부피적분이 음향 추정보다 정보량이 크다**는 점입니다.
학습된 회귀 계수에서 `Stop_Elapsed_Sec`이 가장 큰 영향력을 가졌습니다.
두 신호를 융합하는 것이 이 모듈의 핵심입니다.

| 사용 정보 | 실측 채움률 예측 MAE |
|---|---|
| 음향 추정기 원본 | 4.27 %p |
| 음향 + 학습 보정 | 2.77 %p |
| 시간·유량만 (학습) | 2.32 %p |
| **음향 + 시간·유량 융합** | **1.91 %p** |

## 2. 동작 방식

정지 판단 임계값에 예측 보정량 `e_hat` 을 더합니다.

```
기존:  fill_pct >= TARGET − (STOP_ADVANCE + zone_adv + bridge_adv)
개선:  fill_pct >= TARGET − (STOP_ADVANCE + zone_adv + bridge_adv + e_hat)
```

- `e_hat < 0` — 덜 채울 것으로 예측 → 임계값 상승 → **더 늦게** 정지
- `e_hat > 0` — 넘칠 것으로 예측 → 임계값 하강 → **더 일찍** 정지

`e_hat` 은 "지금 멈추면 최종 오차가 얼마일지"를 예측하는 회귀 모델의 출력입니다.

### 학습 구조 — 2단계

**① 오프라인 사전학습** (`train_fill_corrector.py`)
누적된 `trial_summary.csv` 로 Ridge 회귀 초기 가중치를 만듭니다.

**② 온라인 적응 학습** (`experiment_recorder.finalize_trial` → `fill_corrector.observe`)
급수 1회가 끝나고 실측 채움률이 입력될 때마다 **망각계수 기반 재귀최소자승(RLS)** 으로
가중치를 갱신합니다. 표본을 저장하지 않고 충분통계량 `A`, `b` 만 갱신하므로
메모리 사용량이 시행 수와 무관하게 일정합니다.

```
A ← λA + x xᵀ        b ← λb + x y        w = (A)⁻¹ b        λ = 0.97
```

설치된 개체의 수압·마이크 특성·주변 소음에 사람 개입 없이 맞춰집니다.

### 입력 특징 (17개)

모두 코어가 **런타임에 실제로 아는 값**만 사용합니다.
컵 이름이나 컵 실측 치수처럼 실험 기록용 메타데이터는 쓰지 않습니다.

| 분류 | 특징 |
|---|---|
| 음향 추정 | `Decision_Fill_Pct`, `Estimated_Stop_Air_cm`, `Stop_Freq_Hz`, `Initial_Stable_Freq_Hz`, `Max_Freq_Seen_Hz` |
| 시간·유량 | `Stop_Elapsed_Sec`, `Dynamic_Q`, `Fill_By_Volume_Pct` |
| 센서 융합 | `Fill_Gap_Pct` (음향 − 부피적분), `Air_Ratio` |
| 형상 추정 | `Init_Air_Locked_cm`, `Diameter_cm`, `D_Candidate_MAD_cm` |
| 신뢰도·환경 | `Reg_R2`, `Noise_Floor_Level`, `Bridge_Used`, `Target_Fill_Pct` |

## 3. 검증 결과

`python eval_fill_corrector.py` 로 재현할 수 있습니다.
검증에는 **실제 배포되는 클래스를 그대로** 사용하므로, 아래 숫자가 곧 탑재 모델의 성능입니다.

| 시나리오 | MAE | RMSE | \|오차\|>5%p | 편향 |
|---|---|---|---|---|
| 현재 시스템 (기준선) | 2.71 | 4.45 | 14.6 % | −1.23 |
| 학습된 용기 (무작위 5-겹) | 2.18 | 3.47 | 8.9 % | −0.06 |
| 처음 보는 용기 (용기별 홀드아웃) | 2.53 | 3.79 | 12.6 % | +0.13 |
| **온라인 적응 학습** | **1.99** | 3.44 | **5.5 %** | −0.52 |

온라인 적응 학습은 **미래 데이터를 전혀 쓰지 않고**, 시간순으로 과거 시행만 보고
다음 시행을 예측한 뒤 실측이 나오면 학습하는 실제 운용과 동일한 조건입니다.

```
MAE        2.70 %p → 1.99 %p   (−26 %)
|오차|>5%p  14.5 %  →  5.5 %    (약 1/3)
편향       −1.23   → −0.52
```

| 1~10회 | 1.94 | 2.14 |
| 11~30회 | 2.09 | 2.75 |
| 31회~ | 2.19 | 2.78 |

같은 데이터에서 방식을 비교했습니다. **선형 모델이 부스팅보다 RMSE가 좋습니다.**
493개 표본에 트리 모델은 과적합 구간입니다.

| 방법 | 잔차 MAE | 잔차 RMSE |
|---|---|---|
| 보정 없음 | 4.27 | 6.12 |
| 전역 상수 오프셋 | 3.88 | 5.30 |
| 컵×목표 룩업테이블 | 3.22 | 4.86 |

| GBM (부스팅) | 1.87 | 3.11 |

추론 1회 < 0.05 ms, 갱신 1회 < 1 ms, 의존성은 `numpy` 뿐이라
라즈베리파이에서 실시간 제어 루프에 부담을 주지 않습니다.

## 4. 안전 장치

학습 모델이 제어를 망가뜨리지 않도록 다중 방어를 두었습니다.

| 장치 | 동작 |

| 전역 스위치 | `AI_CORRECTION_ENABLE = False` 로 즉시 비활성 |

## 4-2. 초반 안정성 게이트 [v5.34-EARLY-GATE]

AI 보정과 별개로, **음향 추정이 아예 성립하지 못하는 시행**을 막는 방어층입니다.

### 문제

499회 분석에서 초반(6~10초) raw 주파수의 흔들림이 최종 오차와 직결됐습니다.

| 초반 흔들림 5분위 | n | 락 시각 | MAE | \|오차\|>5%p |
|---|---|---|---|---|
| 안정 Q1 | 99 | 8.93s | 1.97 | 8.1 % |
| Q3 | 99 | 9.23s | 2.51 | 15.2 % |
| 날뜀 Q5 | 99 | 10.74s | 3.62 | 20.2 % |

인과 사슬은 이렇습니다.

```
초반 주파수 날뜀 → 회귀 r² 통과 지연 → D/H 락 지연 → 제어 여유 감소 → 오차 ↑
   (흔들림 vs 락 시각 상관 +0.58,  흔들림 vs |오차| 상관 +0.19)
```

모델 확정에 실패한 6건은 초반 변동량이 196Hz로 정상(39Hz)의 5배였고,
raw의 80.8%가 물리적으로 불가능한 범위에 있었습니다. 이 시행들은
`_init_air <= 0` 이라 정지 조건이 영영 성립하지 않아 **물이 계속 나갔습니다.**

### ① 회귀 입력 게이팅

- **초기 주파수 물리 밴드** — H(5.5~16cm)·D(5~10cm) 허용 범위에서 유도한
  440~1183Hz 밖의 `init_f`는 회귀 입력에서 배제합니다. 컵 목록이 아니라
  코드가 이미 쓰는 물리 제약에서 나온 값이라 새 용기를 막지 않습니다.
- **상승 방향 스파이크 게이트** — 기존에는 주파수 급락만 막았습니다.
  배음 오검출로 인한 급등(`REG_SPIKE_GATE_UP = 0.20`)도 막습니다.

### ② 지터 안전 게이트

- 락(≈9.5초)보다 앞선 **6~8초** 창에서 raw 변동량을 재고, 150Hz를 넘으면 경고합니다.
- **D/H 미확정 상태의 시간 상한** — 목표 채움률에 비례해 잡습니다.
  고정값으로 두면 목표 50%처럼 빨리 끝나는 시행이 그 사이 넘칩니다.

| 목표 | 상한 | 지터 경고 시 |
|---|---|---|
| 50 % | 16.8초 | 13.4초 |
| 60 % | 20.0초 | 17.0초 |
| 70~90 % | 20.0초 | 20.0초 |

### 오프라인 검증 (499회 재현)

| 항목 | 결과 |
|---|---|
| 물리 밴드에 걸리는 정상 시행 | 4건 — 그 4건의 오차가 **+10, +1, +7, −40** (최악 사례 포함) |
| 상승 게이트 차단율 | 정상 1.5 % / 확정 실패 39.9 % |
| 회귀 최소 점수(14) 미달 위험 | **0건** (정상·실패 모두) |
| 시간 상한 오작동 | **0건** (가장 아슬아슬한 시행도 1.3초 여유) |

물리 밴드에 걸린 4건은 오탐이 아니라 실제로 나쁜 시행이었습니다.
평균 |오차| 14.5%p로 전체 평균(2.71%p)의 5배입니다.

### ③ 초기 주파수 확정 검증 [v5.35-INITF-RETRY]

`SPLASH_GUARD_TIME` 을 앞당기면 초반 튐(물이 바닥을 때리는 소리)이 그대로
초기 주파수로 확정돼 버립니다. 실기에서 확인된 실패입니다.

```
[★ 초기주파수 확정] 396Hz | t=1.1s          ← 튐 구간을 잡음
[초반게이트] init_f=396Hz 가 물리 범위 밖 → 회귀 입력 배제 (200회)
[D진단] D=0.00cm | cand=0/14                ← 지름 추정 자체가 실패
```

한 번 잘못 확정되면 그 값 기준의 상대 밴드가 전부 오염되고, 회귀가 영영
성립하지 않습니다. 그래서 **확정 시점에 검사하고, 불합격이면 버리고 다시 모읍니다.**

| 검사 | 기각 조건 |
|---|---|
| 물리 밴드 | 440~1183Hz 밖 (초반 튐·배음 오검출) |
| 안정도 | 버퍼 표준편차/대표값 > 0.15 (아직 요동치는 구간) |
| 폴백 | 12초까지 못 잡으면 그동안 본 밴드 내 최선 후보 채택 |

**시간이 아니라 신호가 준비됐을 때 확정되므로, 가드를 앞당겨도 안전합니다.**
목표 50%처럼 제어 여유가 부족한 경우 가드를 당겨 락을 앞당길 수 있습니다.

### ④ 실측 정합 용기 치수 [v5.36-SHAPE]

코어의 `Diameter_cm` 은 **실제 치수가 아니라 이 음향 모델의 유효 파라미터**입니다.
499회 분석에서 실제 지름 대비 평균 **+1.00cm 과대**였고, 컵마다 편향이 달랐습니다.

| 컵 | 실제 D | 코드 D | 오차 | 테이퍼 |
|---|---|---|---|---|
| flower_cup | 7.00 | 7.55 | +0.55 | 0.0 |
| plastic_mug | 7.50 | 8.37 | +0.87 | 0.0 |
| clear_plastic_cup | 6.85 | 8.13 | +1.28 | 3.3 |
| glass_mug | 6.50 | 8.05 | **+1.55** | **4.0** |

원인이 두 가지 확인됐습니다.

**(1) D 와 H 는 물리적으로 분리되지 않습니다.** 음향은 `f = C / 4(H + K·D)` 이라
**`H + K·D` 라는 합만** 측정합니다. 실제로 D 오차와 H 오차의 회귀 기울기가
**−0.416** 으로 이론값 `−K = −0.35` 와 일치했습니다. D 를 크게 잡으면 H 가
정확히 K 배만큼 작아집니다.

**(2) 테이퍼(원뿔형)가 심할수록 오차가 큽니다** (상관 **+0.400**).
단일 지름 원통 모델의 구조적 한계입니다.

#### 실제 치수를 넣으면 오히려 나빠집니다

정지 시점 주파수는 그대로 두고 D·H 만 실제 치수로 교체해봤습니다.

| | 채움률 MAE |
|---|---|
| 현재 코드 (추정 D·H) | **4.27 %p** |
| D 만 실제값 | 9.12 %p |
| D·H 둘 다 실제값 | 7.92 %p |

`END_CORRECTION_K`, `INIT_AIR_OFFSET` 같은 보정들이 마이크 위치·형상 불일치를
함께 흡수하도록 튜닝돼 있어, D·H 가 그 오차를 나눠 지고 있는 구조입니다.
**따라서 제어에 쓰는 D·H 는 그대로 둡니다.**

#### 표시·기록용으로만 실측에 맞춥니다

```
제어용 D  : 기존 그대로        (정확도 유지)
표시용 D  : 학습 추정기        (실제 치수에 맞춤)
```

| | MAE | 편향 |
|---|---|---|
| 코드 추정 지름 | 1.13 cm | +1.00 |
| **학습 추정 지름 (5-겹)** | **0.29 cm** | 0.00 |
| 학습 추정 지름 (처음 보는 컵) | 0.49 cm | −0.09 |

높이 H 는 학습해도 **처음 보는 컵에서 오히려 나빠져**(0.70 → 1.00cm) 넣지
않았습니다. 코어의 기존 H 추정(MAE 0.70cm, 상대 6.2%)이 이미 충분합니다.

GUI 에는 `지름(D) : 8.05 cm   (실측 7.08 cm)` 처럼 함께 표시되고,
요약 CSV 에 `True_Diameter_cm` 으로 기록됩니다.
학습은 `train_fill_corrector.py` 실행 시 자동으로 함께 이뤄집니다
(`cup_info.csv` 에 실제 상단·하단 지름이 등록된 행만 사용).

### ⑤ 순간 튐 / 배음 즉시 배제 [v5.37-TRANSIENT]

실기 그래프에서 한 샘플짜리 튐(약 1800Hz)이 정지 판단용 EMA에 그대로 반영돼
**약 4초에 걸쳐 천천히 내려오며** 추정을 지연시키는 것이 확인됐습니다.

```
FSCORE_ALPHA_UP   = 0.80   ← 상승은 80% 즉시 반영
FSCORE_ALPHA_DOWN = 0.05   ← 하강은 5%씩만
```

기존 `_is_spike` 플래그는 `max_freq_seen` 갱신만 막고 EMA·중앙값버퍼·회귀는
막지 못했습니다. 그래서 **검출 직후 단계에서** 버리도록 했습니다.

| 검사 | 조건 |
|---|---|
| 배음 | 2배·3배·1/2배 ±20% 이내 |
| 급등 | 주변(직전 5개 중앙값) 대비 1.35배 초과 |
| 급락 | 주변 대비 0.70배 미만 |
| 홀드오프 | 연속 4회 거부되면 실제 이동으로 보고 수용 |

임계값은 정상 시행 250건 11,354샘플의 (raw / 직전5개 중앙값) 분포에서 정했습니다.

```
50%: 1.020   90%: 1.089   95%: 1.129   99%: 1.238   99.9%: 1.790
```

버려진 샘플은 직전 채택값으로 대체되어 EMA·버퍼·회귀 어디에도 들어가지 않습니다.

#### 오프라인 검증 (499회 재현)

| | 시행 수 | 평균 차단 | 차단율 | 최대 연속 |
|---|---|---|---|---|
| 정상 | 494 | 0.21 샘플 | **0.39 %** | 4 |
| 확정 실패 | 6 | 9.50 샘플 | **13.95 %** | 4 |

432/500 시행은 차단 0건이고, 홀드오프 한계에 도달한 6건은 모두 정상 해제됐습니다.
차단이 걸린 시행이 곧 오차가 큰 시행입니다.

| 차단율 | n | 편향 | MAE | \|오차\|>5%p |
|---|---|---|---|---|
| 차단 없음 | 432 | −1.06 | 2.50 | 13.2 % |
| ~3 % | 39 | −1.10 | 2.74 | 15.4 % |
| 3~8 % | 18 | −2.61 | 5.17 | 33.3 % |
| **8 %+** | 4 | **−13.75** | **13.75** | **75.0 %** |

## 7. 한계

정직하게 밝혀 둡니다.

- 위 수치는 **오프라인 재현**입니다. 실제로는 보정이 정지 시점을 바꾸므로 특징값도
  함께 이동합니다(피드백 루프). 0.2초 샘플링 양자화도 있어 **실기 개선폭은
  오프라인 수치보다 다소 작을 수 있습니다.** 현실적 기대치는 MAE 2.0~2.3 %p 구간입니다.
- 용기가 5종뿐이라 "처음 보는 용기" 검증은 한 종을 통째로 빼는 외삽입니다.
  용기 종류가 늘어날수록 이 시나리오의 성능은 개선됩니다.
- `Actual_Fill_Pct` 가 실험자 육안 판독 정수값이라 라벨 자체에 ±0.5 %p 노이즈가 있습니다.
  **MAE 1 %p 이하는 현재 측정 방식으로 검증이 불가능**하며, 그 이하를 목표로 하려면
  저울 기반 실측이 선행되어야 합니다.
- 사용자 실측 입력이 없으면 온라인 학습은 진행되지 않습니다(라벨이 없으므로).
  실험 모드에서 축적한 가중치를 배포하는 방식으로 운용합니다.
